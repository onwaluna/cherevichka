# Правила и регламент разработки проекта

Текущая рабочая конфигурация зафиксирована как базовое состояние проекта.
Дальнейшая работа ведется в режиме аккуратного улучшения интерфейса и дизайна.

## Ограничения и запреты
- Не менять рабочую логику приложения без необходимости;
- Не трогать хосты, API, домены, порты, proxy, DNS, CORS, WebSocket, SSL/TLS и сетевые настройки;
- Не изменять файлы `.env`, `.env.local`, `.env.production` и другие файлы с секретами;
- Не менять `API_BASE_URL`, `BASE_URL`, server URL и значения endpoint без явного разрешения;
- Не переустанавливать зависимости и не менять версии пакетов без предварительного согласования;
- Не менять Docker, nginx, CI/CD и настройки деплоя;
- Не заменять реальные API фиктивными данными;
- Не удалять существующие компоненты и функциональность, если это не требуется для конкретной задачи.

## Разрешенные задачи на этапе улучшения интерфейса и дизайна
- Улучшение визуального дизайна;
- Отступы, размеры, сетка и выравнивание;
- Типографика;
- Цвета и темы;
- Кнопки, карточки, формы и состояния hover / focus / active;
- Адаптивность и мобильная версия;
- Визуальная иерархия;
- Доступность интерфейса (accessibility / a11y);
- Исправление очевидных визуальных дефектов.

## Протокол перед каждым изменением
1. Описать, какие файлы планируется изменить;
2. Объяснить, почему изменения необходимы;
3. Указать, затрагивает ли изменение логику, API или сетевое поведение;
4. Если затрагивается что-либо кроме UI, остановиться и запросить подтверждение пользователя.

## Протокол после каждого изменения
1. Запустить подходящую проверку / тесты;
2. Проверить, что сборка / проект не сломались;
3. Сообщить, какие файлы изменены;
4. Отдельно подтвердить, что хосты, API и сетевые настройки не изменялись.
